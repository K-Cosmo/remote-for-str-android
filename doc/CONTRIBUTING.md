# Contributing

Before a change:

1. read `SOURCE_OF_TRUTH.md`, `GOVERNANCE.md`, `AI_CODING_GUARDRAILS.md` and `CLEAN_CODE.md`;
2. check `FINDINGS.md`, `BLOCKERS.md`, `PLANNED.md` and `BACKLOG.md`;
3. create/update a development spec under `specs/` for non-trivial work;
4. keep the patch focused;
5. run the gates from `TESTS.md`;
6. attach real evidence before claiming verification.

Do not introduce analytics, accounts, hosted backends, Bose branding assets, unnecessary dependencies or native duplicates of STR business logic without an explicit decision.
